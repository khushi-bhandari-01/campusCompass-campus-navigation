



# campusCompass: Interactive NSUT Campus Navigation Using A* Search

campusCompass finds the shortest walking route between two places on the **NSUT (Netaji Subhas University of Technology) campus** and shows, step by step, how the search found it. The search runs in a **Python/FastAPI backend** using an **A\* algorithm written from scratch** (own binary min-heap, OPEN/CLOSED sets, parent tracking, path reconstruction). A **React + Vite** frontend draws the campus as an SVG map and replays the *actual* search trace.


## Objectives
- Implement and visualise an informed search algorithm (A*) on a weighted graph of a real campus.
- Keep the visual map (SVG) and the logical map (graph) synchronised from one JSON file.
- Show real, measured statistics. Nothing is mocked, simulated or hardcoded.

## Features
- **NSUT campus map** with 19 selectable locations: 2 gates (North Gate, Main Gate) and 17 buildings and grounds (Amul Ground, APJ Halls, Smart Block, Clinic, NESCII 1 and 2, Admin, Main Auditorium, Blocks 4, 5 and 6, Fountain, SAC Library, Basketball Court, Running Track, CBT & Mini Auditorium, Cricket Ground).
- Graph of **39 nodes** (2 gates, 20 road junctions, 17 building entrances) and **44 weighted edges**.
- Click-to-select source and destination on the map, or use the dropdowns; swap, reset, and optional road-junction picking.
- Live animation of the real search trace: current node, OPEN, CLOSED and the final route. Controls: play, pause, step forward and back, restart, scrub bar, speed 0.5x to 4x.
- Per-step panel showing g(n), h(n), f(n), the parent node, the neighbours checked and the OPEN list.
- Analytics panel: route distance (metres), nodes explored, nodes generated, nodes in route, execution time, heap pushes, stale heap entries skipped and nodes re-opened.
- Clear message when no route exists; loading and error states.
- Benchmark module comparing A* with Dijkstra (time, nodes, cost, success rate, memory).

## Quick start
Backend (terminal 1):
```bash
cd backend
python -m venv .venv
# Windows PowerShell:  .venv\Scripts\Activate.ps1      macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```
Frontend (terminal 2):
```bash
cd frontend
npm install
npm run dev
```
Open http://localhost:5173 (API docs at http://127.0.0.1:8000/docs). In development the Vite dev server proxies `/api` to the backend, so no extra configuration is needed. Full beginner guide: [docs/INSTALLATION_GUIDE.md](docs/INSTALLATION_GUIDE.md).

## Algorithm
f(n) = g(n) + h(n), with Euclidean distance as h(n). Edge weights are Euclidean length times a factor of at least 1, so h is admissible and consistent and A* returns an optimal route. Distances are converted to metres using a scale of 0.8 m per map unit. See [docs/ALGORITHM_EXPLANATION.md](docs/ALGORITHM_EXPLANATION.md).

## Editing the campus map
`backend/map_data/campus_map.json` is generated by a script. To change locations, roads or scale, edit `backend/map_data/build_nsut_map.py` (node coordinates, edges, buildings, `METERS_PER_UNIT`) and re-run:
```bash
cd backend
python map_data/build_nsut_map.py
```

## Deployment
- **Backend (Render):** root directory `backend`, build command `pip install -r requirements.txt`, start command `uvicorn main:app --host 0.0.0.0 --port $PORT`. Set `ALLOWED_ORIGINS` to your Vercel URL. `render.yaml` can set this up automatically.
- **Frontend (Vercel):** root directory `frontend`. Set `VITE_API_BASE_URL` to your Render URL (no trailing slash), then redeploy whenever it changes, because Vite bakes it in at build time.

Full steps: [docs/VERCEL_DEPLOYMENT.md](docs/VERCEL_DEPLOYMENT.md).

## Known limitations
- The map is a **schematic redrawn by hand** from the NSUT campus map, not imported from GPS or OpenStreetMap data. Paths and distances are approximate.
- Free Render services sleep after inactivity, so the first request can take about a minute.
- Memory usage is measured only in the benchmark (via `tracemalloc`), not per API request.
- The animation timer replays the trace at a chosen speed; the displayed execution time is measured separately on the untraced search.
- Frontend has no automated tests (verified by production build and manual testing); backend has 21.
